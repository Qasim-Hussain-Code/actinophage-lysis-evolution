# Candidate-only Lysin B profile diagnostic

Design fixed on 2026-10-17, before any target HMM score is inspected. The earlier assay-panel expansion and its lack of additional supported B calls motivated this secondary diagnostic. It is not a preregistration of the original study. No candidate from this diagnostic changes primary functional confidence, architecture, eligibility, hypothesis tests or candidate rankings.

## Training and fixed settings

The broad training panel contains exactly nine assay-supported proteins: D29_LysB, Ms6_LysB, WXIN_LysB, Omega_LysB, Saal_LysB, Obama12_LysB, SWU1_LysB, BabyRay_LysB and Palestino_LysB. Their frozen sequences and assay tiers come from the isolated profile-panel reference manifest. The six added proteins and WXIN do not individually establish native mycolylarabinogalactan substrate specificity through their generic lipolytic assays. A narrower sensitivity model contains only D29_LysB and Ms6_LysB, the two references with more specific substrate evidence. Three published Gordonia B predictions are evaluation queries only and never training sequences.

Training uses no cohort proteins, genomic positions, annotations or neighborhood outcomes. Exact duplicate training sequences are represented once, with every alias retained in provenance. There is no iterative target recruitment, manual sequence addition, alignment trimming or post-score threshold tuning. Synthetic API tests were used to verify constructor compatibility before any cohort score; the installed 0.7.0 FAMSA signature, rather than an older API default, fixes medoid_threshold 2000, medoid_seeds 100, medoid_sample 2000, medoid_evaluations 1, cluster_fraction 0.1 and cluster_iters 2. These medoid settings do not activate with nine training proteins. The pinned package's native default PFASUM43 matrix is checked at runtime. Passing its name through the external matrix loader was rejected by this installed API because of alphabet handling; the native default preserves the verified matrix without that incompatible override.

PyFAMSA 0.7.0 aligns each training set separately with four threads, single-linkage guide tree, no tree heuristic, 100 refinement iterations and the pinned package's default PFASUM43 scoring matrix. Its installed transitive dependencies scoring-matrices 0.3.5 and psutil 7.2.2 are also pinned and recorded. Each alignment is saved. PyHMMER 0.12.3 builds a fresh HMM using amino-acid background frequencies, fast architecture, position-based weighting, entropy effective sequence number, alphabet mixture priors, symfrac 0.5, fragthresh 0.5, wid 0.62, esigma 45, eid 0.62, EmL/EmN/EvL/EvN 200, EfL 100, EfN 200, Eft 0.04 and seed 20261016. Other optional Builder overrides remain None; constructor settings and available runtime settings are recorded with each model. The installed constructor spelling fragthresh is used because the online docstring's fragthres spelling differs from the actual pinned API. HMM creation-time metadata is cleared before ASCII export without modifying model probabilities or scores; the actual Builder seed is stored as an integer.

Every validation and cohort search fixes both Z and domZ at 2460, the frozen cohort CDS count, irrespective of how many queries are searched in a fold. Composition-bias filtering and null2 correction remain enabled. Search filters retain F1=0.02, F2=0.001 and F3=1e-5; sequence and domain reporting limits are E=10. No HMM search uses more than four workers. All reported full-sequence and domain scores, E-values, biases, alignment coordinates and coverage values are retained with reported/included flags. For each domain, let P be the number of alignment columns containing both a model match-state residue and a target residue. HMM insertion dots and target deletion gaps do not contribute to P. Primary model coverage is P divided by the complete model length; primary target coverage is P divided by the complete target length. Model-coordinate and target-coordinate span coverages are also recorded separately as diagnostics; they are not used for the 70% candidate cuts. Disjoint domains are not combined to cross a coverage threshold.

A profile candidate must have full-sequence E <= 1e-6 and at least one domain with independent domain E <= 1e-6, model coverage >= 0.70 and target coverage >= 0.70. These criteria do not have a sequence-identity equivalent and do not establish biochemical specificity. No-hit and failing-query statuses are retained rather than silently omitted. Exact cohort sequence aliases of training references are identified as in-training observations, not independent discoveries.

## Reference-only validation

Source-held-out folds remove every training protein from the held-out resolved nucleotide-accession base and every exact sequence alias of those proteins. Family-held-out folds use connected components of a graph constructed only from the nine assay-reference sequences. Edges require a global BLOSUM62 alignment with identity >= 0.40 and both aligned-residue coverages >= 0.70, with gap open -10 and extension -0.5. Identity includes gap columns; coverage counts residues paired to residues, so global alignment does not make coverage automatically one. These components are operational similarity groups, not independent clades, and transitive membership does not guarantee that every pair meets the edge thresholds.

Every fold rebuilds its MSA and HMM from the remaining training sequences. A fold with no training sequence is explicitly untestable. Reference recovery summaries count queries and unique sequence hashes separately. The narrow model uses the same reference-only graph with its training subset; it cannot claim family-held-out validation when removal empties that subset.

Evaluation also includes all frozen non-B curated reference proteins, all three frozen PDB cellular-enzyme specificity challenges, and the three Gordonia computational B predictions. A challenge passing the candidate cuts is a potential cross-family flag, not proof that the cellular enzyme lacks every possible mycolate-related activity. Gordonia prediction matches are computational transfer only. Recovery of a generic assay reference is not a substrate-specific sensitivity estimate. Few assay proteins and coarse groups limit validation and do not justify a population specificity, false-discovery rate or evolutionary independence claim.

## Isolation and provenance

The CLI requires `--root`, `--validation-dir` and `--out`. It reads the isolated root's frozen reference FASTA/manifest and all 2460 CDS translations, plus the previously frozen validation queries and their checksums. Before the first diagnostic freeze, stage-2 and stage-3 receipts must authenticate the CDS table and both reference inputs; the receipt file itself becomes a frozen input. It performs no downloads. MSA files, HMMs, training IDs and aliases, fold memberships, pairwise grouping metrics, raw reported-hit ledgers, query summaries and model metadata remain under the new output directory. Input hashes are checked before and after execution. Script and protocol checksums use canonical LF text to preserve portability across Git checkouts; scientific input and artifact checksums authenticate their exact bytes. Output paths are relative, with no home paths or environment dump. Measured wall time, peak process resident memory and project storage are recorded. Existing core files and baseline outputs are never overwritten. Changed inputs, source code, protocol or optional-library versions require a separate output freeze.

The implementation follows the official [PyFAMSA interoperability guide](https://pyfamsa.readthedocs.io/en/stable/guide/interfacing.html), [PyHMMER Builder and Pipeline reference](https://pyhmmer.readthedocs.io/en/stable/api/plan7/pli.html), [HMM-building example](https://pyhmmer.readthedocs.io/en/stable/examples/msa_to_hmm.html), and [result definitions](https://pyhmmer.readthedocs.io/en/stable/api/plan7/results.html).
